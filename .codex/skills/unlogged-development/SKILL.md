# 《未登录的人》开发

将用户指定的体验目标落实到可玩的游戏中。沿用仓库 `AGENTS.md` 的内容边界、目录职责和验证要求；评审报告是设计输入，不会自动授权实施其中全部建议。

## 实施判断

- 先确认当前工作树和本轮改动范围。剧情改动读 `docs/story-bible.md`、对应章节流程及相关实现；视觉资产改动再读角色母版。
- 推荐 Web 版以 `src/story/` 承载内容与状态，以 `src/App.tsx` 和 CSS 承载运行时与界面。维持内容数据与 UI 分离，并评估旧本地存档是否需要迁移。
- 涉及 Ren'Py 时同步关键情节、状态与界面行为；若用户只指定一个版本，说明另一版本的差异和后续同步需求。
- 选择必须具有与文字语义一致、可被玩家察觉的后果。新增异常应有可观察证据，不在第一章揭示 N 的真实身份。
- 文案变化按 `AGENTS.md` 重建字体子集；结构变化同步章节流程及相关文档。

## 交付判断

按改动风险验证受影响的路径。涉及剧情或状态时覆盖三个结局及主要分支；涉及 UI 时检查桌面与移动端；涉及声音时检查静音和浏览器首次交互后的播放。运行 Web 构建；Ren'Py 无法运行时如实说明。最终报告改动、验证结果、尚存限制和 `git status --short` 中的预期文件。
